# 方法介绍

## 总体思路

本项目不是重新开发一个外部悬浮窗应用，而是把补丁运行时和 AMap Companion 主要功能一起注入到高德车机版 APK 内。高德创建原悬浮窗时，补丁把原来的 `WindowManager.addView(...)` 调用替换为 `PatchRuntime.replaceHostFloatWindow(...)`。运行时启动同进程内的 `com.autonavi.companion.OverlayService`，由它显示自定义悬浮窗。

## 代码分层

- `patch.ps1`：完整 APK 构造流水线，负责校验输入 APK、编译 runtime、反编译 APK、应用 smali 补丁、回编、zipalign、签名和验证。
- `profiles/9.1.0.600087.json`：版本适配 profile，记录目标 APK SHA-256、包名、输出名、smali 文件和插入标记。
- `runtime/src/main/java/amap/auto/patch/PatchRuntime.java`：注入后的运行时入口，初始化 companion、替换原悬浮窗、转发红绿灯 wrapper。
- `companion/src/main/java/com/autonavi/companion/PatchBridge.java`：高德补丁运行时和 companion 代码之间的桥接层。
- `companion/src/main/java/com/autonavi/companion/OverlayService.java`：悬浮窗 UI、样式、轮播、广播接收、插件渲染和位置保存。
- `companion/src/main/java/com/autonavi/companion/MainActivity.java`：同 APK 内的 `AMap Companion` 设置入口。
- `companion/src/main/res/`：合入高德资源表的悬浮窗布局、图标和样式。
- `build-test-apk.ps1` 和 `test_app/`：虚拟机测试壳，用来不依赖高德主程序验证 runtime UI。

## 注入点

当前 profile 使用四个 patch：

- `applicationPatch`：在 `MapApplicationProxy.onCreate()` 后插入 `PatchRuntime.init(context)`，保证高德启动时运行时初始化。
- `hostFloatWindowPatch`：把原悬浮窗的 `WindowManager.addView(view, params)` 替换成 `PatchRuntime.replaceHostFloatWindow(wm, view, params)`。
- `trafficLightPatch`：在高德内部红绿灯 wrapper 更新后插入 `PatchRuntime.onTrafficLightWrapper(wrapper)`。
- `hostFloatWindowCleanupPatch`：原悬浮窗关闭时同步调用 `PatchRuntime.removePatchOverlay()`。

## 数据来源

运行时使用两类数据：

- 标准动态广播：`OverlayService` 监听 `AUTONAVI_STANDARD_BROADCAST_SEND`，解析导航、巡航、车道、电子眼、TMC、前后台等状态。
- 高德内部对象：在红绿灯 wrapper 更新位置直接注入调用，由 `PatchBridge.onTrafficLightWrapper(...)` 通过反射读取字段并转成 companion 可处理的 extras。

红绿灯优先使用内部 wrapper，因为实际测试中标准广播未必稳定透出红绿灯倒计时。导航仍按标准广播读取。

## APK 构造方式

runtime 和 companion 先由 `javac` 编译为 class，再由 `d8` 转成 `runtime.dex`。脚本用 apktool 把 `runtime.dex` 转成 smali，复制到原 APK 解包目录的 `smali/amap/...`、`smali/com/autonavi/companion/...` 和必要的 D8 注解目录下，最终和原 `classes.dex` 一起由 apktool 回编。

这样做的原因是只改一个 dex 的 smali 结构，避免直接往 APK 里追加新的 `classes2.dex` 后触发安装解析或签名校验兼容问题。

## companion 集成

脚本会把 companion 资源复制到高德 `res/`，并把以下组件写入 Manifest：

- `com.autonavi.companion.MainActivity`：`AMap Companion` 桌面入口。
- `com.autonavi.companion.DiagnosticActivity`：诊断页面。
- `com.autonavi.companion.OverlayService`：悬浮窗前台服务。
- `com.autonavi.companion.BootReceiver`：开机、替换安装、亮屏后恢复服务。

集成版锁定目标包名为当前高德包名，并移除 APK 更新、下载和安装器入口。
