# 如何适配新版本

每个高德 APK 版本都需要单独 profile。不要复用旧版本 profile 直接补新 APK，因为混淆类名、方法体和 smali 标记都可能变化。

## 新建 profile

复制现有文件：

```powershell
Copy-Item profiles\9.1.0.600087.json profiles\新版本号.json
```

修改：

- `id`：构建目录名称，建议包含版本号。
- `versionName`：高德版本号。
- `packageName`：目标包名。
- `inputSha256`：目标 APK SHA-256。
- `outputName`：输出 APK 名称。
- `minApi`：目标最低 API，通常保持 23。
- 各 patch 的 `file`、`after`、`find`、`replace`。

计算 SHA-256：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath "D:\path\to\amap.apk"
```

## 解包新版本

```powershell
java -jar tools\apktool.jar d -f -r -o D:\tmp\amap_decoded "D:\path\to\amap.apk"
```

使用 `-r` 保留原始资源，因为本项目只改 smali/dex，避免不必要的 res 回编风险。

## 查找 Application 注入点

目标是在高德 Application 的 `onCreate()` 后调用：

```smali
invoke-static {p0}, Lamap/auto/patch/PatchRuntime;->init(Landroid/content/Context;)V
```

当前版本文件：

```text
smali/com/autonavi/amapauto/app/MapApplicationProxy.smali
```

如果新版本类名变化，可先看 `AndroidManifest.xml` 的 `application android:name`，再在 smali 目录中找到对应类。

在方法里找：

```smali
.method public onCreate()V
...
invoke-super {p0}, Landroid/app/Application;->onCreate()V
```

profile 的 `after` 要选稳定且只出现一次的行。

## 查找原悬浮窗替换点

目标是找到高德原悬浮窗调用：

```smali
invoke-interface {...}, Landroid/view/WindowManager;->addView(Landroid/view/View;Landroid/view/ViewGroup$LayoutParams;)V
```

然后替换成：

```smali
invoke-static {...}, Lamap/auto/patch/PatchRuntime;->replaceHostFloatWindow(Landroid/view/WindowManager;Landroid/view/View;Landroid/view/ViewGroup$LayoutParams;)V
```

当前版本在：

```text
smali/vh0.smali
```

新版本查找命令：

```powershell
rg "WindowManager;->addView\\(Landroid/view/View;Landroid/view/ViewGroup\\$LayoutParams;\\)V" D:\tmp\amap_decoded\smali
```

可能会有多个 `addView`。判断是否为悬浮窗可以看附近代码：

- 是否构造 `WindowManager$LayoutParams`。
- 是否设置窗口 type、flags、gravity、x、y。
- 是否在同一类里有关闭或移除悬浮窗的方法。
- 是否和高德 float、camera、traffic、cruise 相关类互相调用。

## 查找悬浮窗清理点

目标是在原悬浮窗关闭方法开头调用：

```smali
invoke-static {}, Lamap/auto/patch/PatchRuntime;->removePatchOverlay()V
```

当前版本在 `vh0.smali` 的：

```smali
.method public declared-synchronized d()V
```

新版本可在同一个原悬浮窗类中查找：

```powershell
rg "removeView|removeViewImmediate" D:\tmp\amap_decoded\smali\候选类.smali
```

找到移除原 view 的方法后，把 `scope` 设置到该方法声明，`after` 设置到方法内稳定开头，例如 `monitor-enter p0` 或 `.locals` 后第一段可插入位置。

## 查找红绿灯 wrapper 注入点

当前版本文件：

```text
smali/com/autonavi/amapauto/CameraLightInfo/CameraLightInteract.smali
```

当前 marker：

```smali
invoke-static {p0}, Lfloatapp/trafficlight/CruiseTrafficLightVoice;->setCameraLightInfoWrapper(Lcom/autonavi/amapauto/CameraLightInfo/CameraLightInfoWrapper;)V
```

插入：

```smali
invoke-static {p0}, Lamap/auto/patch/PatchRuntime;->onTrafficLightWrapper(Ljava/lang/Object;)V
```

新版本查找方式：

```powershell
rg "CameraLightInfoWrapper|CruiseTrafficLightVoice|setCameraLightInfoWrapper|trafficlight" D:\tmp\amap_decoded\smali
```

如果 wrapper 类名没变但方法变了，优先找高德内部接收红绿灯 wrapper 的地方，在 wrapper 对象刚更新后插入调用。

## 修改 wrapper 字段

如果新版本红绿灯对象字段名变了，改 `DataModel.fromTrafficLightWrapper(...)`：

```java
List<?> lights = PatchRuntime.readListField(wrapper, "a");
Integer status = PatchRuntime.readIntField(item, "d");
Integer seconds = PatchRuntime.readIntField(item, "e");
Integer dir = PatchRuntime.readIntField(item, "c");
```

字段变化的判断方法：

- 用 jadx 查看 wrapper 类结构。
- 用 smali 搜索字段读写。
- 临时把 `readObjectField` 和 `readIntField` 附近加日志，输出候选字段值。

## 验证新 profile

先只跑构建：

```powershell
.\patch.ps1 -InputApk "D:\path\to\new.apk" -Profile "profiles\新版本号.json"
```

如果失败，按错误定位：

- SHA-256 mismatch：输入 APK 和 profile 不一致。
- patch marker not found：smali 标记变化，需要重新找插入点。
- apktool build failed：回编失败，查看 apktool 输出和是否误改资源。
- apksigner verify failed：签名流程或 APK 对齐异常。

构建通过后，在真实 ARM/ARMv7 环境中验证：

- 高德能启动。
- 原悬浮窗出现位置被替换。
- 长按能打开设置。
- 导航广播能刷新。
- 红绿灯 wrapper 能刷新。
- 关闭高德悬浮窗或退出导航时自定义悬浮窗不残留。
