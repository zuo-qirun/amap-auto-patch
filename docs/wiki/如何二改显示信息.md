# 如何二改显示信息

显示信息由 `DataModel.java` 负责解析，由 `OverlayController.java` 负责选择哪个分类显示。大多数“显示什么字段”“字段怎么格式化”“是否轮播巡航”等需求，只需要改这两个文件。

## 数据模型

`DataModel` 的核心字段：

```java
int keyType;
String action;
String mode;
String primary;
String secondary;
int lightStatus;
int lightSeconds;
int lightDir;
int lightsCount;
int category;
```

悬浮窗实际渲染的是：

- `mode` -> 分类标签。
- `primary` -> 主行。
- `secondary` -> 副行。

## 分类

当前分类常量：

```java
CATEGORY_NONE = 0;
CATEGORY_NAV = 1;
CATEGORY_TRAFFIC_LIGHT = 2;
CATEGORY_CRUISE = 3;
```

当前轮播顺序在 `OverlayController`：

```java
private static final int[] DISPLAY_ORDER = new int[] {
        DataModel.CATEGORY_NAV,
        DataModel.CATEGORY_TRAFFIC_LIGHT
};
```

如果要恢复巡航显示，改成：

```java
private static final int[] DISPLAY_ORDER = new int[] {
        DataModel.CATEGORY_NAV,
        DataModel.CATEGORY_TRAFFIC_LIGHT,
        DataModel.CATEGORY_CRUISE
};
```

## 修改轮播时间

当前每 3 秒切换一次：

```java
private static final long SLOT_MS = 3000L;
```

改成 5 秒：

```java
private static final long SLOT_MS = 5000L;
```

数据超过 `STALE_MS` 会被认为过期，不再显示：

```java
private static final long STALE_MS = 30000L;
```

## 修改导航显示

导航广播在 `DataModel.fromBroadcast(...)` 的 `KEY_ROUTE_GUIDANCE` 分支：

```java
if (model.keyType == KEY_ROUTE_GUIDANCE) {
    model.mode = "导航";
    model.category = CATEGORY_NAV;
    model.primary = firstString(extras,
            "NEXT_ROAD_NAME", "NEXT_ROAD", "ROUTE_ROAD_NAME", "ROAD_NAME", "EXTRA_ROAD_NAME", "roadName");
    model.secondary = firstString(extras,
            "SEG_REMAIN_DIS", "ROUTE_REMAIN_DIS", "NEXT_ROAD_DISTANCE", "EXTRA_DISTANCE", "distance");
    normalizeEmpty(model, "导航数据");
    return model;
}
```

如果要显示下一道路和剩余距离，可优先使用：

- `NEXT_ROAD_NAME`：下一道路名。
- `SEG_REMAIN_DIS`：当前导航段剩余距离，单位米。
- `ROUTE_REMAIN_DIS`：全路径剩余距离，单位米。
- `SEG_REMAIN_DIS_AUTO`：转换后的当前导航段剩余距离，通常带单位。
- `ROUTE_REMAIN_DIS_AUTO`：转换后的全路径剩余距离，通常带单位。

示例：副行优先显示带单位字段：

```java
model.secondary = firstString(extras,
        "SEG_REMAIN_DIS_AUTO", "ROUTE_REMAIN_DIS_AUTO", "SEG_REMAIN_DIS", "ROUTE_REMAIN_DIS");
```

## 修改红绿灯显示

红绿灯有两个来源：

- 广播：`DataModel.fromBroadcast(...)` 中 `KEY_TRAFFIC_LIGHT` 或包含 `trafficLightStatus`、`redLightCountDownSeconds`、`lightsData` 的分支。
- 内部 wrapper：`DataModel.fromTrafficLightWrapper(...)`。

实际改版高德主要依赖内部 wrapper。当前 wrapper 字段按观察结果读取：

- wrapper 字段 `a`：红绿灯列表。
- item 字段 `d`：状态。
- item 字段 `e`：倒计时秒数。
- item 字段 `c`：方向。
- item 字段 `a`：等待数量。
- item 字段 `f`：显示类型。

状态文本由 `lightText(...)` 决定：

```java
status == 1 -> 即将绿灯
status == 2 -> 绿灯
status == 3 -> 黄灯
status == 4 -> 即将红灯
```

方向文本由 `directionText(...)` 决定：

```java
1 -> 左转
2 -> 右转
3 -> 掉头
4 -> 直行
```

如果实车发现方向值不同，优先改 `directionText(...)`。

## 选择哪个红绿灯

`fromTrafficLightWrapper(...)` 会遍历所有灯组，给每个灯组打分，选择最像有效倒计时的灯：

- 秒数大于 0 加分。
- 状态大于 0 加分。
- 秒数在 4 到 10 之间额外加分。

如果要固定优先直行，可以在评分里增加：

```java
if (dir != null && dir.intValue() == 4) {
    score += 3;
}
```

## 新增一个显示字段

例如要在副行显示当前速度：

1. 在 `DataModel.fromBroadcast(...)` 对应分支读取 extra。
2. 写入 `model.secondary`。
3. 如果字段是数字，用 `intValue(extras, "CUR_SPEED", -1)`。
4. 如果字段可能是字符串，用 `firstString(extras, "CUR_SPEED", "SPEED")`。

示例：

```java
int speed = intValue(extras, "CUR_SPEED", -1);
model.secondary = speed >= 0 ? "车速 " + speed + " km/h" : readableExtras(extras);
```

## 新增一个分类

1. 在 `DataModel` 增加 `CATEGORY_...` 常量。
2. 在 `fromBroadcast(...)` 里识别新的 `KEY_TYPE` 或 extra 字段。
3. 设置 `model.mode`、`model.primary`、`model.secondary`、`model.category`。
4. 在 `OverlayController` 增加缓存字段，例如 `private DataModel xxxModel; private long xxxUpdatedAt;`。
5. 在 `rememberModel(...)` 和 `getFreshModel(...)` 里处理新分类。
6. 把新分类加入 `DISPLAY_ORDER`。

## 调试未知广播

对于暂不认识的广播，`DataModel` 会把部分 extras 拼成文本。可以临时把 `readableExtras(extras)` 输出到日志：

```java
Log.i("AmapAutoPatch", "extras=" + readableExtras(extras));
```

也可以用 adb 主动回放：

```powershell
adb shell am broadcast -a AUTONAVI_STANDARD_BROADCAST_SEND --ei KEY_TYPE 10001 --es NEXT_ROAD_NAME "人民路" --ei SEG_REMAIN_DIS 320
```
