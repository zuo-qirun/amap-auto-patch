# 如何构建

## 环境要求

- Windows PowerShell。
- JDK，需可执行 `java` 和 `javac`。
- Android SDK build-tools，需包含 `d8`、`zipalign`、`apksigner`、`aapt`。
- Android platform `android.jar`。
- apktool，自行放到 `tools/apktool.jar`，或运行脚本时传入 `-ApktoolJar`。
- 一个用于调试签名的 keystore。默认路径是 `..\amap_companion\debug.keystore`。

`patch.ps1` 会按以下顺序寻找 Android SDK：

- `ANDROID_HOME`
- `ANDROID_SDK_ROOT`
- `C:\Users\zuoqirun\AppData\Local\Android\Sdk`

可以用环境变量指定版本：

```powershell
$env:ANDROID_BUILD_TOOLS_VERSION = "35.0.0"
$env:ANDROID_PLATFORM = "android-35"
```

## 准备文件

把目标高德 APK 放在本机任意路径。当前 profile 只接受 SHA-256 为 `ACEB25EBA296FBFCC78B103BD3360A9026FB89AFC50FE07FB1C6E0D214342512` 的 `9.1.0.600087` 版本。

把 apktool 放到：

```text
tools/apktool.jar
```

不要把 APK 或 apktool.jar 提交到 Git。`.gitignore` 已忽略 `*.apk`、`dist/`、`build/` 和 `tools/*.jar`。

## 构建真实改包

```powershell
cd D:\Github\红绿灯\amap_auto_patch
.\patch.ps1 -InputApk "D:\Github\红绿灯\高德地图_9.1.0.600087 (巡航红绿灯).apk"
```

输出：

```text
dist/高德地图_9.1.0.600087_amap_auto_patch_signed.apk
```

脚本默认把中间目录放到系统临时目录 `amap_auto_patch_build`，避免中文路径影响 apktool 或 aapt2。可用 `-WorkDir` 指定其他目录。

## 使用外部 apktool

```powershell
.\patch.ps1 `
  -InputApk "D:\path\to\amap.apk" `
  -ApktoolJar "C:\tools\apktool.jar"
```

## 使用外部 keystore

```powershell
.\patch.ps1 `
  -InputApk "D:\path\to\amap.apk" `
  -Keystore "D:\keys\debug.keystore" `
  -KeyAlias "androiddebugkey" `
  -KsPass "android" `
  -KeyPass "android"
```

## 构建虚拟机测试壳

真实高德 APK 只有 ARM native 库，普通 x86/x86_64 Emulator 无法作为真实高德运行环境。可以先构建测试壳验证悬浮窗 UI：

```powershell
.\build-test-apk.ps1
adb -s emulator-5554 install -r -t .\dist\amap_auto_patch_vm_test.apk
adb -s emulator-5554 shell appops set amap.auto.patch.test SYSTEM_ALERT_WINDOW allow
adb -s emulator-5554 shell monkey -p amap.auto.patch.test -c android.intent.category.LAUNCHER 1
```

## 构建成功判定

构建成功时应看到：

```text
[patch] verify
Verifies
[patch] done: ...\dist\高德地图_9.1.0.600087_amap_auto_patch_signed.apk
```

`apksigner verify` 应显示 v1/v2/v3 签名通过。真实 APK 需要在 ARM/ARMv7 兼容车机或系统中最终安装验证。
